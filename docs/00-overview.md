# 프로젝트 개요

## 목적과 범위

신규 광고주 랜딩에 독립형 Tracking SDK를 적용하고, 사내 직원이 로그인 화면 없이 업체를 선택해 광고 설정을 관리하는 MVP를 목표로 합니다. 추후 회사 관리자 시스템의 인증·권한·접근 프록시에 연결합니다. 공개 포트폴리오 시연에는 가상 업체와 가상 ID만 사용합니다.

## 현재 구현

- 관리자: 가상 업체/다중 사이트 검색·선택, siteId 중복 방지 데모 등록, 6개 매체 설정 편집, 초안/데모 게시/롤백/이력, 대시보드
- 공통 패키지: 공개 게시 설정 타입과 허용 필드 검증
- SDK: 게시 설정 fetch, 제한된 재시도, 중복 시도 방지, Next.js식 History 이동 감지, /complete?token 감지, 어댑터 주입 인터페이스
- 서버/CLI: 문서와 경계만 존재. Firestore·CDN·매체별 어댑터·실제 진단은 미구현

데모 게시본은 브라우저 메모리에서만 유지되고 SDK 공개 API로 제공되지 않습니다. 화면의 SDK 상태는 가상 값이며 실제 설치 확인이 아닙니다.

## 개발 단계

1. 사내 태그 사용 현황과 중복 제거 계획 확인 (1일차: 현재 저장소 조사·실행 기준 정리 완료, 실제 랜딩/GTM 증거 미확인)
2. 접근 게이트 및 서버 API 계약·Firestore Rules 확정
3. 사이트 등록 CLI와 Firestore 저장 구현
4. 6개 매체 어댑터와 실제 랜딩 통합 시험
5. 게시 JSON/CDN·롤백·진단·운영 검증

## MVP 완료 기준

- [x] 로그인 없는 데모 관리자 흐름 및 가상 데이터
- [x] 관리자/공개 SDK 설정 계약 분리
- [ ] 사내 접근 게이트로 보호된 관리자 쓰기 API
- [ ] Firestore Rules의 클라이언트 쓰기 차단 검증
- [ ] 사이트 자동 등록 CLI의 인증 및 siteId 멱등성
- [ ] 6개 매체의 검증된 공통/전환 어댑터
- [ ] 실제 문의 성공 이벤트 및 /complete 이동 통합 시험
- [ ] CDN 게시/캐시/롤백과 감사 로그
- [ ] 기존 하드코딩 태그 중복 제거 및 광고 플랫폼 진단

## 제외

MVP 로그인 UI, 직원별 업체 권한 관리 UI, 임의 JavaScript 실행, MLeverage SDK 수정, 광고 플랫폼 집계 보장은 범위에 넣지 않습니다.

실제 랜딩의 태그 위치와 문의 성공 조건이 확인되기 전에는 어댑터 구현이나 태그 교체를 완료로 표시하지 않습니다. 조사 표와 확인할 증거는 [1일차 기록](daily/day-01.md)에 있습니다.
