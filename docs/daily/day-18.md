## 작업 메모

- 화면: 첨부된 관리자 화면을 참고해 흰색 3열 레이아웃(메뉴·업체 빠른 이동·작업 영역)과 `#e88731` 주색을 적용했다. 900px 이하에서는 업체 패널을 숨기고 720px 이하에서는 메뉴를 가로 스크롤로 바꾼다. 검색·필터, 표의 행 링크, 키보드 포커스 색을 적용했다. 업체와 SDK 상태는 모두 가상 데이터다.
- 데모 감사 로그: 초안·게시·롤백·등록 시 `demo-operator`, 전후 버전, 시각을 기록한다. 배포 이력 화면에서 사이트와 작업별로 필터링한다. 이 기록은 새로고침 시 사라진다.
- 서버 감사 조회: `functions/src/auditHistory.ts`의 `listSiteAudit`은 사이트 범위 `readHistory` 인가를 먼저 확인하고 최신 1~100건을 조회한다. 반환 필드는 작업, 주체, 전후 버전, 요약, 시각이며 최초 등록의 이전 버전은 `null`이다. 관리자 HTTP 라우트는 아직 없다.
- SDK 신호: `TrackingSdkOptions.onDiagnostic` 선택 콜백에 설정 로드, 어댑터 초기화/오류, 동의 차단, 준비, 초기화 실패를 전달한다. `adapter_setup`은 외부 태그의 네트워크 로드나 광고 플랫폼 수신 성공을 뜻하지 않는다. siteId·릴리스 버전·매체만 포함하고 완료 토큰, 광고 ID, URL, 오류 메시지는 포함하지 않는다. 콜백은 로컬에서만 실행되고 자동 서버 전송은 없다.
- 판정 정책: 운영에서 검증된 수집 경로와 수신 시각이 없으면 `미확인`이다. 미설치는 단순한 신호 부재로 판정할 수 없다. 향후 수집에는 인증된 사이트 매핑, 동의·보관 기간·전송 실패 정책, 중복/속도 제한, SDK 버전과 설정 버전, 서버 수신 시각을 추가해야 한다. 실제 랜딩에서의 설치와 매체 수신 여부는 이 데모로 확인할 수 없다.
- 검증: `npm test` 63건, `npm run test:ui` 3건, `npm run test:release` 3건, `npm run typecheck`, `npm run build` 통과. 1440px Edge 렌더링을 확인했다. 에뮬레이터의 동시 쓰기 테스트에서는 예상된 트랜잭션 잠금 경고가 출력됐지만 3건 모두 통과했다.
- 남은 이슈: 회사 게이트와 관리자 HTTP, 운영 Firestore/인덱스 배포, 진단 수집 API와 실제 랜딩 계측은 미구현이다. 19일차 실제 랜딩 연동 후에만 운영 진단 판정을 활성화한다.
