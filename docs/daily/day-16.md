## 작업 메모

- 구현 파일: `apps/admin/src/App.tsx`, `apps/admin/src/lib/demoWorkspace.ts`, `apps/admin/src/styles/mvp.css`, `tests/script-editor.test.mjs`, `tests/admin-ui.test.mjs`.
- 편집 동작: 6개 매체의 공통 스크립트와 전환 이벤트를 분리해 추가·수정·비활성화·제거한다. 전환 추가 시 활성 공통 설정이 있는 매체만 선택 가능하다. 공통 설정을 끄거나 제거하면 연결된 전환도 함께 비활성화하며, 공통을 다시 켜도 전환은 사용자가 직접 재활성화한다. 기존 설정의 매체 변경은 차단한다.
- 검증과 이력: 모든 편집은 공통 DTO 검증을 통과한 경우에만 초안 버전과 이력을 갱신한다. AW ID·send_to 일치, Naver 유입 도메인, 매체별 지원 이벤트를 확인하며 오류를 화면에 표시한다. 이력에는 추가·수정·활성화·비활성화·제거 동작을 남긴다.
- 테스트 결과: `npm test` 60건, `npm run typecheck`, `npm run build` 통과. `npm run test:ui`는 설치된 Edge에서 잘못된 AW ID 오류, 공통·전환 추가, 수정, 상태 토글, 데모 게시 미리보기, 제거 이력을 실제 화면 조작으로 확인했다. 6개 매체의 필드와 공통 없는 전환 차단은 모델 테스트로 확인했다.
- 남은 이슈: 관리자 게시본은 브라우저 메모리 데모이며 실제 SDK 공개 설정 API·Firebase·CDN·광고 플랫폼과 연결되지 않았다. UI 브라우저 테스트는 로컬 Edge와 가상 데이터 기준이다.
