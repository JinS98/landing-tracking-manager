## 작업 메모

- 구현 파일: `packages/tracking-sdk/src/index.ts`, `tests/sdk-init.test.mjs`.
- 동작: siteId를 조회 전에 검증한다. `fetch`와 JSON 본문 읽기에 1회 제한 시간을 적용하고 네트워크·타임아웃·5xx만 최대 두 번 시도한다. 404와 잘못된 게시 설정은 다시 요청하지 않는다. 공개 API ETag 재검증을 위해 `cache: 'no-cache'`로 조회한다. 같은 창·siteId의 SDK 두 개는 한 주체의 설정 조회, 태그 로드, 라우트 감지를 공유한다.
- 동의와 실패 경계: 동의가 없으면 태그를 로드하지 않으며 이후 `start()`로 다시 시도할 수 있다. 활성 공통 태그만 로드하고 성공한 매체에 대해서만 전환을 허용한다. 어댑터 실패와 `onError` 콜백 실패가 `start()`에서 바깥으로 전파되지 않는다.
- 테스트 결과: `npm test` 48개 통과(초기화 신규 6개), `npm run typecheck`와 `npm run build` 통과. 잘못된 siteId·게시본, 404, 오프라인, 응답/본문 지연, 중복 SDK 삽입, 동의 거부, 어댑터 일부 실패를 확인했다.
- 남은 이슈: 실제 랜딩에서 동의 획득·철회, CSP/네트워크 차단, SPA 라우터와 문의 성공 콜백의 실행 순서를 검증해야 한다. 이미 로드한 외부 픽셀은 설정 변경·동의 철회 때 자동 제거하지 않는다. SDK 배포 번들과 공개 API 운영 배포도 아직 없다.
