# 테스트 계획과 완료 기준

## 지금 실행 가능한 검사

    npm run typecheck
    npm run build
    npm test

브라우저 데모 시나리오:

1. 로그인 화면 없이 대시보드 진입; 업체/사이트/활성 매체 수와 최근 이력 확인
2. 업체명·siteId·도메인 검색, 한 업체의 여러 사이트 선택
3. 가상 사이트 등록 후 동일 siteId 재등록 차단 확인
4. 매체별 공통 ID 입력, Naver 유입 도메인 필수값, Google Ads AW 형식 확인
5. 공통 매체가 없을 때 전환 추가 차단; 추가·수정·비활성화·제거 확인
6. 초안과 게시본 미리보기, 데모 게시, 변경 후 이전 버전 롤백, 이력 확인
7. 새로고침 후 데모 상태 초기화; Firebase/광고 플랫폼 네트워크 쓰기 없음 확인

현재 npm test(Node.js 22.14+)는 siteId 중복, 데모 게시/롤백 불변 이력, 공개 설정의 필드 투영을 검사합니다.

## 서버 구현 후 자동화

- [ ] 익명·권한 없는 관리자 API 쓰기/게시/롤백 401/403
- [ ] Firestore Rules의 브라우저 직접 쓰기·초안 읽기 거부
- [ ] siteId 중복 등록 및 동시 요청 멱등성, 기존 설정 보존
- [ ] expectedVersion 충돌 409, 릴리스 버전 단조 증가, 롤백 새 버전 생성
- [ ] 공개 API는 게시본만 반환하고 비밀/PII/초안/감사 정보 제외
- [ ] CDN ETag/TTL/무효화, 게시 실패 시 이전 버전 유지

## SDK와 실제 랜딩 검증

- [ ] 6개 매체 공통 로더와 전환 어댑터의 공식 API 및 진단 도구 확인
- [ ] GTM/Google Ads dataLayer 충돌과 기존 하드코딩/GTM 내부 태그 중복 방지
- [ ] Next.js 초기 로드, pushState/replaceState/popstate와 /complete?token 진입
- [ ] 실제 문의 성공 콜백 기반 track 호출, 재방문·새 탭·네트워크 지연 중복 시도
- [ ] 동의 거부/철회, 외부 스크립트 차단, 리다이렉트 시간 제한
- [ ] SDK 오류가 문의 폼·페이지 성능을 방해하지 않는지 확인

## 운영 완료 기준

위 서버·SDK 항목이 통과하고 사내 접근 게이트, Firestore Rules, 실사이트 태그 인벤토리, 게시/롤백 절차가 검증되기 전에는 운영 배포 완료로 표시하지 않습니다. 현재 완료된 것은 메모리 데모 UI, SDK 공통 구조, 3개의 상태/검증 테스트와 타입/빌드 검사입니다.
