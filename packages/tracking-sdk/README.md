## tracking-sdk

게시 설정 조회, 제한된 fetch 재시도, 중복 시도 방지, History API 및 검증된 /complete?token 전환 감지, 매체 어댑터 인터페이스를 포함합니다. GTM·Google Ads·Naver WCS·당근·Meta·TikTok 어댑터는 각각 `createGtmAdapter()`, `createGoogleAdsAdapter()`, `createNaverWcsAdapter()`, `createKarrotAdapter()`, `createMetaAdapter()`, `createTikTokAdapter()`로 제공하며 **명시적으로 주입했을 때만** 사용합니다. 배포 번들은 아직 없습니다. `start()`는 유효한 siteId로 게시본을 조회하고, 네트워크·타임아웃·5xx만 최대 두 번 시도합니다. 중복 SDK 인스턴스는 같은 사이트의 초기화를 공유합니다. 동의가 없으면 태그를 로드하지 않으며 이후 `start()`로 다시 시도할 수 있습니다. `track`은 문의 서버가 실제 접수를 확정한 뒤 고유 eventId와 함께 호출해야 합니다. 완료 URL만 방문하면 전환하지 않습니다. 경로 기반 전환이 필요하면 서버에 token을 조회해 확인된 접수의 안정적인 eventId를 반환하는 `verifyCompletionToken` 옵션을 제공해야 합니다. 초기 로드와 pushState·replaceState·popstate를 감지하며, 검증 함수가 없거나 실패하면 전환하지 않습니다. Naver의 `inflowDomain`은 쿠키 도메인이며 현재 호스트와 일치하거나 상위 도메인이어야 합니다. `purchase` 전환은 금액 설정이 없어 지원하지 않습니다. 당근·Meta·TikTok의 상담 완료 이벤트는 각각 `SubmitApplication`, `Lead`, `SubmitForm`입니다. 기존 하드코딩 태그와 GTM 내부 태그를 확인하기 전에는 같은 전환에 두 실행 주체를 켜지 않습니다. 현재 검증은 모의 DOM 테스트이며 실제 랜딩·픽셀 진단 도구·광고 플랫폼 수신 결과는 확인되지 않았습니다. docs/03-sdk-spec.md 참조.
