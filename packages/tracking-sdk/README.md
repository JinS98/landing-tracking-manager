## tracking-sdk

게시 설정 조회, 제한된 fetch 재시도, 중복 시도 방지, History API 및 랜덤 token 기반 /complete 전환 감지, 매체 어댑터 인터페이스를 포함합니다. GTM·Google Ads·Naver WCS·당근·Meta·TikTok 어댑터는 각각 `createGtmAdapter()`, `createGoogleAdsAdapter()`, `createNaverWcsAdapter()`, `createKarrotAdapter()`, `createMetaAdapter()`, `createTikTokAdapter()`로 제공하며 **명시적으로 주입했을 때만** 사용합니다. 배포 번들은 아직 없습니다. `start()`는 유효한 siteId로 게시본을 조회하고, 네트워크·타임아웃·5xx만 최대 두 번 시도합니다. 중복 SDK 인스턴스는 같은 사이트의 초기화를 공유합니다. 동의가 없으면 태그를 로드하지 않으며 이후 `start()`로 다시 시도할 수 있습니다. 문의 성공 후 랜덤 token을 발급해 `/complete?token=...`로 이동하면 SDK가 해당 token으로 전환을 시도합니다. 같은 탭의 뒤로 가기·재방문·새로고침은 sessionStorage 키로 다시 보내지 않습니다. `verifyCompletionToken`은 선택적 추가 검증입니다. 직접 `track`을 호출할 수도 있으며 동일 접수에 두 경로를 쓰면 같은 ID를 전달해야 합니다. 기존 문의·페이지뷰 SDK는 매체 픽셀과 별개입니다. 초기 로드와 pushState·replaceState·popstate를 감지합니다. Naver의 `inflowDomain`은 쿠키 도메인이며 현재 호스트와 일치하거나 상위 도메인이어야 합니다. `purchase` 전환은 금액 설정이 없어 지원하지 않습니다. 당근·Meta·TikTok의 상담 완료 이벤트는 각각 `SubmitApplication`, `Lead`, `SubmitForm`입니다. 기존 하드코딩 태그와 GTM 내부 태그를 확인하기 전에는 같은 전환에 두 실행 주체를 켜지 않습니다. 현재 검증은 모의 DOM 테스트이며 실제 랜딩·픽셀 진단 도구·광고 플랫폼 수신 결과는 확인되지 않았습니다. docs/03-sdk-spec.md 참조.

## 18일차 진단 콜백

`TrackingSdkOptions.onDiagnostic`은 설정 로드, 어댑터 로드/실패, 동의 차단, 준비, 초기화 실패를 호출자에게 알리는 선택적 로컬 콜백입니다. 신호에는 `kind`, `siteId`, 선택적인 `releaseVersion`·`provider`만 담습니다. SDK는 이 값을 자동 전송하지 않으며, 콜백 실패는 랜딩 실행을 막지 않습니다. 실제 진단 수집은 사이트 권한 검증, 동의 정책, 수신 시각과 보관 정책을 마련한 뒤 연결해야 합니다. 콜백이 없거나 수집되지 않은 사이트의 운영 상태는 미확인입니다.
